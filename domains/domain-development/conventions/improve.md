# Improving a domain

The improvement loop is one FPEV cycle whose subject is a domain. [run]

**observe → propose → necessity pass → apply → check application → check consistency → run on itself → owner rules → deploy → use → feedback** [run]

## Observe

Use two channels, because each finds what the other misses. [run]

- **The field:** real projects, their departures (R4s), corrections and complaints. [run]
- **The bench:** fresh agents in a clean room, on scenarios and planted faults. [run]

The field calibrates the bench: a bench is credible to the degree that it reproduces frictions the record shows people met. [run]

## Propose

- Each proposal names the file, the change and the case behind it. [run]
- Agents propose diffs and never edit the installed domain. [run]

## Necessity pass

Ask two questions of every proposal: [owner]

- **Real gap or polish?** [run]
- **Name a case where its absence went wrong.** [run]

No case, no change. A process that produces findings faster than an owner can rule will otherwise grow the domain without limit. [run]

## Apply and check

- Check that the change was applied as ruled. [run]
- Check that it did not contradict the rest of the domain or FPEV. [run]
- Re-run the checker and affected tests. [run]
- Compare length before and after. A gain bought with length must be stated. [run]

## Measure value, not only conformance

A fresh-reader test shows conformance only. Keep a per-use record, from material each domain already keeps: [run]

- **Attention:** the owner's prompts and corrections per cycle, the number of Verify phases, and the time to verdict. [inferred] Falsified if these do not track the owner's own sense of effort.
- **Quality:** defects found after release. [run]
- **Understandability:** whether the owner can explain the result and the domain's core without the file, and whether a fresh agent can resume from the handoffs. [owner]
- **Insight:** positions the owner took that changed the frame or result, recorded in Verify. [inferred] Falsified if such counts do not distinguish useful cycles from routine ones.

A domain improves when attention falls, or moves to Verify, while none of the four criteria falls. [owner]

## Rule

Present few proposals, ranked, each with evidence. The owner adopts, defers or rejects, in their own words, and the ruling is recorded verbatim. [run]

## When to start an improvement cycle

- A recorded departure recurs in two projects. [inferred] Falsified if single departures predict later ones as well.
- The owner reports a felt regression. [owner]
- A platform version changes (`maintain.md`). [run]
- A model or tool a domain depends on changes. [run]

## Splitting and merging

Split a domain when the same strikes keep recurring in the same places. Until then, one domain with exceptions beats two that drift. [external]
